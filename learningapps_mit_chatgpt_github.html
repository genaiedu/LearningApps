Von der Idee zur veröffentlichten LearningApp

Mit ChatGPT & GitHub selbst Lernapps bauen

Du brauchst keine Programmiererfahrung. Dieses Arbeitsblatt erklärt jeden Begriff, richtet deinen Mac oder Windows-PC ein und führt dich mit kopierbaren Befehlen von der Idee über den Test bis zur Veröffentlichung.

Voraussetzung für diesen Kurs: Wir setzen ein kostenpflichtiges ChatGPT-Abo mit Projekt- und Codebearbeitung und ein GitHub-Konto voraus. Funktionen und Nutzungslimits können sich je nach Tarif und Arbeitsbereich ändern.

Alles geschieht in derselben ChatGPT-App

Du musst nicht zwischen verschiedenen Programmen wechseln. ChatGPT kann mit dir die Unterrichtsidee klären und im selben Arbeitsablauf das Projekt lesen, Dateien erstellen, die LearningApp prüfen und sie für GitHub vorbereiten. Je nach Version können dabei Bezeichnungen wie Work oder Codex erscheinen. Für dich sind das Arbeitsweisen innerhalb derselben ChatGPT-App. Du beschreibst dein Ziel und kontrollierst das Ergebnis vor der Veröffentlichung.

Was du brauchst

Hake erst weiter, wenn alle drei Voraussetzungen erfüllt sind.

ChatGPT-Abo

Ein kostenpflichtiges Abo mit Projekt- und Codebearbeitung. Die offizielle App gibt es auf chatgpt.com/download.

GitHub-Konto

GitHub speichert das Projekt, seine Geschichte und die veröffentlichte Version. Anmeldung: github.com/signup.

Eigener Computer

Mac oder Windows-PC, Internet und die Erlaubnis, Git sowie GitHub CLI zu installieren.

GitHub für Laien: ein Projektordner mit Zeitmaschine

GitHub ist ein Internetdienst, auf dem Softwareprojekte gespeichert, gemeinsam bearbeitet und veröffentlicht werden.

Stell dir einen gemeinsamen Ordner vor, der jede gespeicherte Version kennt. Du kannst eine Idee in einer eigenen Spur ausprobieren. Andere sehen die Änderung, und erst nach der Kontrolle wird sie in die Hauptversion übernommen. Das Versionssystem heißt Git; die Website und Zusammenarbeit darum herum heißt GitHub.

Deinen Computer einrichten

Wähle dein Betriebssystem. Danach siehst du nur die passende Anleitung.

Terminal öffnen: Drücke ⌘ + Leertaste, tippe Terminal und drücke Enter. Kopiere nur einen Block auf einmal.
1

Apple-Werkzeuge bereitstellen

Öffnet Apples Installationsfenster. Sind die Werkzeuge vorhanden, meldet der Mac das.

xcode-select --install
2

Homebrew installieren

Homebrew ist ein Paketmanager für Terminal-Werkzeuge.

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
Wichtig: Am Ende zeigt Homebrew unter „Next steps“ zwei Befehle. Führe genau diese aus, sonst kennt das Terminal brew noch nicht.
3

Homebrew auf aktuellen Macs aktivieren

Für Apple-Chips (M1, M2, M3, M4 …) sind dies meist die „Next steps“:

echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile eval "$(/opt/homebrew/bin/brew shellenv)"

Auf älteren Intel-Macs steht meist /usr/local statt /opt/homebrew. Nimm den Text aus deiner Homebrew-Ausgabe.

Git und GitHub CLI installieren

git verwaltet Versionen; gh verbindet das Terminal mit GitHub.

brew install git gh

Das GitHub-Projekt auf den Computer holen

Einmalig den Namen für Speicherpunkte festlegen

Git schreibt Name und E-Mail an jeden Commit. Nutze eine bei GitHub bestätigte Adresse. Wenn deine Adresse nicht öffentlich werden soll, kopiere zuerst deine private noreply-Adresse aus GitHub → Settings → Emails.

git config --global user.name "Vorname Nachname" git config --global user.email "deine-adresse@example.de"
Zugriffsrecht: Für ein fremdes Repository brauchst du Schreibzugriff. Wenn git push später abgelehnt wird, muss die Eigentümerin dich einladen oder du arbeitest über einen eigenen Fork.

Schriften, Symbole und Recht
Eine schöne LearningApp soll keine unnötigen Daten an Dritte senden und die verantwortliche Person klar nennen.

  

    
A. Was sind Google Fonts?

    
Google Fonts ist eine Sammlung frei lizenzierter Schriftarten. Eine Schrift kann entweder beim Öffnen der Seite von Google geladen oder als Datei im eigenen Projekt bereitgestellt werden. Beim Laden über fonts.googleapis.com oder fonts.gstatic.com baut der Browser eine Verbindung zu Google auf. Dabei erhält Google unter anderem die IP-Adresse sowie technische Angaben zu Browser, Betriebssystem und aufgerufener Seite.

    

      
Nicht für dieses Projekt: Ein externer <link> zu Google Fonts spart zwar das Herunterladen, erzeugt aber beim Seitenaufruf eine zusätzliche Datenübertragung an Google.

      
Regel in diesem Repository: Schriften liegen als .woff2-Dateien im Ordner fonts. Dadurch lädt der Browser sie vom selben Webauftritt. Das ist datensparsamer, offline-tauglich und vermeidet die Google-Verbindung.

    

    
So wird eine lokal vorhandene Schrift eingebunden:

    
@font-face {
  font-family: "Inter";
  src: url("fonts/inter-v20-latin-regular.woff2") format("woff2");
  font-weight: 400;
  font-style: normal;
  font-display: swap;
}

body { font-family: "Inter", system-ui, sans-serif; }

    
Wichtig: Nur die tatsächlich benötigten Schriftschnitte laden, möglichst woff2 verwenden und die Lizenzdatei der Schrift im Repository aufbewahren. „Google Fonts“ bedeutet nicht automatisch „Google Sans“ oder „Product Sans“; verwende nur ausdrücklich offen lizenzierte Familien.


    
Sinnvolle Grundausstattung für den Ordner fonts

    
Diese Auswahl deckt fast alle Arbeitsblätter ab und ist in diesem Projekt bereits vorhanden:

    

      
Inter
Sehr gut lesbarer Fließtext und Bedienelemente: 400, 500, 600, 700.

      
Poppins
Prägnante Überschriften: 600, 700, 800, 900.

      
DM Sans oder Outfit
Freundliche Alternative für moderne Lernseiten: 400/500 bis 700.

      
Lora
Ruhige Serifenschrift für längere Lesetexte: 400 und 700.

      
DM Mono
Für Code, Formeln und Zahlenbeispiele: 400 und 500.

      
Nunito
Weiche, gut lesbare Alternative für jüngere Lerngruppen: 400 und 700.

    

    
Dekorschriften wie Caveat, Dancing Script, Bebas Neue oder Bangers nur sparsam für kurze Akzente verwenden – nie für längere Aufgaben oder kleine Beschriftungen.


    
B. Was sind Lucide-Symbole?

    
Lucide ist eine offen lizenzierte Sammlung einheitlicher SVG-Symbole, zum Beispiel Buch, Schild, Gehirn oder Glühbirne. Die Symbole helfen bei der Orientierung, ersetzen aber keine verständlichen Beschriftungen. Wird die Bibliothek über ein CDN geladen, entsteht wieder eine Verbindung zu einem fremden Server. Deshalb verwendet dieses Projekt die lokale Datei fonts/lucide.min.js.

    
<script src="fonts/lucide.min.js"></script>

<button aria-label="Zur Übersicht">
  <i data-lucide="layout-grid" aria-hidden="true"></i>
  Zur Übersicht
</button>

<script>lucide.createIcons();</script>

    
Lizenz und Barrierefreiheit: Lucide steht unter der ISC-Lizenz. Der Lizenzhinweis in der lokalen Datei darf nicht entfernt werden; sinnvoll ist zusätzlich eine zentrale Lizenzübersicht. Icons erhalten bei reiner Dekoration aria-hidden="true". Ein alleinstehender Symbol-Button braucht einen verständlichen Namen mit aria-label.


    
C. Impressum der Übersichtsseite

    
Die Übersichtsseite index.html ist öffentlich und dient nicht nur persönlichen oder familiären Zwecken. Deshalb sollte sie ein leicht erkennbares, unmittelbar erreichbares und ständig verfügbares Impressum tragen. Der Link gehört in den Footer jeder öffentlich erreichbaren Seite.

    

      
Offizielles Schulprojekt: Verwende das von Schulleitung oder Schulträger freigegebene Schul-Impressum. Typisch sind Name und ladungsfähige Anschrift der verantwortlichen Einrichtung, Vertretungsberechtigte sowie E-Mail und eine weitere schnelle Kontaktmöglichkeit. Wer rechtlich Betreiber ist, muss die Schule beziehungsweise der Schulträger festlegen.

      
Privates Lehrkräfte-Projekt: Ist eine Lehrkraft selbst Betreiberin oder Betreiber, können vollständiger Name und ladungsfähige Anschrift erforderlich sein. Eine private Wohnadresse sollte nicht unüberlegt veröffentlicht werden. Vorher mit Schulträger, Schulleitung oder Rechtsberatung klären, ob die Seite institutionell übernommen werden kann.

    

    
    
      
  • Für nicht rein persönliche Angebote nennt § 18 Abs. 1 Medienstaatsvertrag mindestens Name und Anschrift; bei juristischen Personen zusätzlich die vertretungsberechtigte Person.
    • 
      
  • Bei geschäftsmäßigen, in der Regel gegen Entgelt angebotenen Diensten kommen die Angaben aus § 5 Digitale-Dienste-Gesetz hinzu, zum Beispiel Kontakt-, Register-, Aufsichts- oder Umsatzsteuerangaben, soweit sie tatsächlich zutreffen.
    • 
      
  • Bei journalistisch-redaktionellen Inhalten kann zusätzlich eine inhaltlich verantwortliche Person nach § 18 Abs. 2 Medienstaatsvertrag nötig sein.

D. Welche Datenschutzerklärung wird benötigt?

    
Die Datenschutzerklärung muss den wirklichen technischen Betrieb beschreiben – nicht nur einen allgemeinen Mustertext. Auch eine statische Seite verarbeitet beim Hosting meist IP-Adressen in Server-Protokollen. Bei GitHub Pages, Vercel oder einem anderen Hoster müssen dessen Rolle, Empfänger, Speicherfristen und mögliche Übermittlungen außerhalb von EU/EWR geprüft werden. Für ein Schulangebot ist ein vom Schulträger freigegebener Hoster die sicherste Wahl.

    

      
Mindestens aufnehmen
  • Verantwortliche Stelle und Kontaktdaten
  • Datenschutzbeauftragte Person, falls vorhanden
  • Hosting und Server-Logfiles: Datenarten, Zweck, Rechtsgrundlage, Empfänger und Speicherdauer
  • Betroffenenrechte und zuständige Aufsichtsbehörde
  • Stand der Erklärung und Kontakt für Datenschutzfragen

      
Nur wenn tatsächlich genutzt
  • Cookies oder Browser-Speicher wie localStorage
  • Formulare, E-Mail-Kontakt oder Nutzerkonten
  • Statistik-, Video-, Karten- oder andere Drittanbieter
  • Auftragsverarbeiter und Drittlandübermittlungen
  • Einwilligung und jederzeitiger Widerruf bei nicht notwendigen Zugriffen

    

    
Beispiel dieses Arbeitsblatts: Lernfortschritt und Darstellungswahl werden mit localStorage nur im Browser gespeichert und nicht an das Projekt übertragen. Auch das muss in der Datenschutzerklärung genannt und vor Veröffentlichung auf Erforderlichkeit oder Einwilligung geprüft werden.

    
Datensparsame Variante: Alle Schriften, Symbole, Bilder und Skripte lokal; keine Werbung, Analyse, externen Videos, Karten oder Social-Media-Plugins; keine Formulare; keine unnötigen Cookies oder Browser-Speicher. Dann ist meist kein Einwilligungsbanner nötig. Die Datenschutzerklärung bleibt trotzdem erforderlich, vor allem wegen Hosting und Server-Logfiles.

    
Keine Rechtsgarantie: Ob ein Speicherzugriff „unbedingt erforderlich“ ist, ob der Hoster zulässig eingebunden ist und wer Betreiber ist, hängt vom konkreten Einsatz ab. Vor der öffentlichen Freischaltung sollten Schulleitung beziehungsweise Betreiber und Datenschutzbeauftragte die fertigen Texte und den Hoster prüfen.

    
Diese Links müssen von jeder Seite aus erreichbar sein:

    
<footer>
  <a href="impressum.html">Impressum</a>
  <span aria-hidden="true"> · </span>
  <a href="datenschutz.html">Datenschutz</a>
</footer>

Prüfen, hochladen und veröffentlichen
Die Hauptversion wird erst verändert, wenn du die LearningApp geprüft hast.

  

    
A. Lokal im Browser prüfen
Öffne die Übersicht. Die neue Karte muss funktionieren.

    
Mac
open index.html
Windows
start index.html

    

    
B. Als sicheren Vorschlag hochladen

    

    
1 · Status
Zeigt die veränderten Dateien.
git status

    
2 · Branch
Erzeugt eine eigene Arbeitsspur.
git switch -c agent/fotosynthese-arbeitsblatt

    
3 · Auswählen
Wählt Übersicht und neue App aus.
git add index.html fotosynthese_arbeitsblatt.html

    
4 · Commit
Erstellt den Speicherpunkt.
git commit -m "Interaktives Fotosynthese-Arbeitsblatt ergänzen"

    
5 · Push
Lädt den Branch zu GitHub.
git push -u origin agent/fotosynthese-arbeitsblatt

    
6 · Pull Request
Öffnet einen Entwurf zur Prüfung.
gh pr create --draft --fill --base main

    
C. Nach Prüfung veröffentlichen

    
Nicht sofort zusammenführen: Öffne den PR-Link, lies „Files changed“, teste die Vorschau und bitte möglichst eine zweite Person um Kontrolle.

    
Entwurf bereit markieren
gh pr ready
Nach Freigabe übernehmen
gh pr merge --squash --delete-branch

    
Danach die lokale Hauptversion aktualisieren:
git switch main
git pull

    
GitHub ist noch nicht automatisch die Webseite: Bei einem verbundenen Hoster wie Vercel wird main oft automatisch veröffentlicht. Für GitHub Pages: Repository → Settings → Pages → Deploy from a branch → main → /(root) → Save. GitHub zeigt danach die Webadresse.

Wenn etwas nicht funktioniert
Öffne die passende Fehlermeldung.

  

    
Homebrew ist installiert, aber noch nicht im Suchpfad. Führe die „Next steps“ des Installers aus. Auf Apple-Chip-Macs meist:
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"

    
Schließe das gesamte Terminal- oder PowerShell-Fenster und öffne ein neues. Bleibt der Fehler, installiere gh erneut.

    
Codes laufen ab. Brich mit Ctrl + C ab und beginne neu:
gh auth login --web --git-protocol https

    
Prüfe Schreibweise und Zugriff. Dieser Befehl zeigt das angemeldete Konto:
gh auth status

    
Prüfe, ob der PR zusammengeführt wurde. Öffne danach auf GitHub Actions oder Settings → Pages.
